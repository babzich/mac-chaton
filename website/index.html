01 Mental model

First, separate the layers.

Most confusion comes from calling every layer “the agent.” Experts name the owner, boundary, and failure mode precisely.

Click a layer to inspect its responsibility and the question it answers.

LAYER 07 / USER BOUNDARY

The surface is not the agent.

A terminal UI, editor panel, or SwiftUI app captures intent and renders state. It may own permission UX and process lifecycle, while the agent lives behind a protocol boundary.

Owns
Input, navigation, rendering, user decisions
Asks
What must the human see, decide, or recover?
LeChaton
SwiftUI views + app-owned controllers
A

The universal agent loop

  1. 1Assemble instructions, history, files, and tool schemas into model context.
  2. 2Ask the model for the next response; stream text, reasoning, or tool intent.
  3. 3Authorize and execute tool calls in the runtime’s environment.
  4. 4Append tool results to context and call the model again.
  5. 5Stop on a terminal response, limit, refusal, cancellation, or error.
B

Three nested lifetimes

Processowns pipes, cwd, env, descendants
Sessionowns history and configuration
Turnone prompt → stop reason
C

ACP ≠ MCP

ACP connects a user-facing client to a coding agent. MCP connects a model or agent to external tools and data. An ACP client can hand MCP server definitions to the agent—two boundaries, two trust models.

CONTEXT INPUTS

What the model actually sees

System prompt + active agent profile + global/project instructions + selected skills + conversation + referenced files + tool schemas + tool results. The repository is not magically “inside” the model; the harness selects and injects context.

SAFETY PROFILE

Approval is policy, not intelligence

default asks before tools, plan favors read-only work, accept-edits auto-approves edits, and auto-approve removes prompts. The model proposes; the runtime policy decides whether execution may happen.

DURABLE CUSTOMIZATION

Config, agents, skills, MCP

~/.vibe/config.toml provides user defaults; .vibe/ can add project-local configuration after trust; agents package behavior and tool policy; skills add workflows; MCP servers add external tools.

A notification has a method but no ID. session/update carries message chunks, reasoning, tools, plans, and metadata.

THE REPLAY TRAP / VIBE 2.21.0

            
The response is not the history.

            
During session/load, Vibe can emit replayed session/update notifications before returning the load response. A client that waits for the response before consuming stdout can lose or misorder history.

            
    
              
  • Start one permanent, lossless read loop before session requests.
    • 
              
  • Stage history off-screen and reduce updates serially.
    • 
              
  • Capture a replay barrier at the load response.
    • 
              
  • Publish only after every earlier sequence is reduced.
    •

NON-NEGOTIABLES
Six rules for trustworthy clients

          
    
            
  1. One owner per mutable resource.Pipes, reducers, database handles, auth attempts, and process trees each need an explicit owner.
    2. 
            
  2. Events need identity and order.Correlate runtime generation, load attempt, sequence, session, message, and tool IDs.
    3. 
            
  3. Rendering is not persistence.Know whether the agent or client is authoritative for history, configuration, and titles.
    4. 
            
  4. Cancellation is a protocol plus cleanup.A cancel notification does not prove shell descendants are dead.
    5. 
            
  5. Capabilities beat assumptions.Negotiate optional behavior and tolerate unknown enum values, fields, and notifications.
    6. 
            
  6. Secrets move on narrow paths.Sanitize the environment, scope key injection, and never log credentials or completion payloads.
    7. 
          

        


        

          

            
FROM TOY LOOP TO PRODUCT

            
A harness is a control system around an unreliable planner.

          

          
The model is probabilistic. Your harness must make context, tools, side effects, budgets, events, and recovery deterministic enough to operate. The craft is not “calling an LLM”; it is designing every boundary around that call.

THE MINIMAL CORE

            
Write the loop in 30 lines. Spend the rest of the project on invariants.

            
The happy path is deliberately boring. Production complexity enters through partial streaming, retries, permission races, context limits, provider differences, tool processes, and crash recovery.

            

              
I-01
Each accepted tool call produces at most one terminal tool result.

              
I-02
Every public event is ordered within a run and belongs to one session and turn.

              
I-03
No retry may duplicate a non-idempotent side effect without an explicit key or decision.

              
I-04
Context compaction preserves active goals, constraints, decisions, and unresolved tool work.

              
I-05
Cancellation stops future scheduling and eventually proves owned execution is gone.

            

          

          

            
PSEUDOCODE / PROVIDER-NEUTRAL

            
while budget.allows(state):
  request = context.build(state, tools.schemas)
  stream = provider.generate(request, signal)
  decision = events.reduce(stream)

  if decision.is_final:
    return decision.output

  for call in decision.tool_calls:
    verdict = policy.authorize(call, scope)
    result = tools.execute(call, verdict, signal)
    state.append(result)

return StopReason.budget_exhausted

          

        


        

          

            CTX
            
Context engineering

            
Define precedence and token budgets. Keep durable instructions separate from task input. Retrieve files just in time. Preserve the user’s goal through compaction. Treat tool output as untrusted, high-volume input.

            
  • instruction layering
  • retrieval policy
  • prompt-cache boundaries
  • compaction contract

          

          

            API
            
Provider normalization

            
Convert provider-specific streams into your own events. Do not let Anthropic content blocks, OpenAI response items, or Mistral deltas leak across the core. Preserve unknown fields for diagnostics.

            
  • model capabilities
  • tool-call deltas
  • usage accounting
  • retry classification

          

          

            TLS
            
Tool design

            
A tool is a typed capability, not a shell-shaped escape hatch. Give it a narrow schema, explicit effect class, bounded output, stable call ID, timeout, cancellation path, and renderer-safe result.

            
  • schema quality
  • idempotency
  • output truncation
  • effect annotations

          

          

            EVT
            
Event architecture

            
Emit semantic facts: turn started, text delta, tool proposed, permission requested, tool completed, usage updated, turn stopped. Keep transport frames private and make reducers replayable.

            
  • monotonic sequence
  • correlation IDs
  • snapshot + replay
  • forward compatibility

          

          

            SEC
            
Execution safety

            
Layer model-visible guidance, deterministic policy, human approval, OS sandboxing, scoped credentials, and complete child-process ownership. No single layer substitutes for another.

            
  • allow / ask / deny
  • workspace roots
  • network policy
  • secret routing

          

          

            EVAL
            
Evals & observability

            
Measure task outcome and trajectory quality. Store event traces without secrets. Track tool errors, retries, context growth, latency, cost, approval friction, cancellation success, and orphan processes.

            
  • deterministic fixtures
  • trajectory assertions
  • live compatibility gates
  • regression corpus

CODEXDefense in depth

            
Codex separates the model’s proposed actions from the local executor with an OS-enforced sandbox and a distinct approval policy. Its CLI exposes interactive and non-interactive modes; its app-server and SDK expose thread/turn events to richer clients.

            
    
              
  • AGENTS.md makes repository guidance durable.
    • 
              
  • config.toml controls model, sandbox, approvals, MCP, and profiles.
    • 
              
  • codex exec --json streams machine-readable thread and item events.
    • 
              
  • Codex can consume MCP servers and can itself run as an MCP server.
    • 
            

            Official CLI manual ↗
          

          

            
PISmall core, wide seams

            
Pi makes the harness legible: model adapter, four core tools, session tree, TUI, and extension hooks. It supports many providers and invites you to add permission gates, sandboxing, subagents, custom tools, UI, or remote execution as extensions.

            
    
              
  • Sessions are append-only JSONL entries linked by id and parentId.
    • 
              
  • Interactive, print/JSON, RPC, and SDK modes share one core.
    • 
              
  • Extensions can intercept lifecycle events and replace tools or rendering.
    • 
              
  • Minimalism makes ownership easy to study—and safety your responsibility.
    •

VIBE 2.21.0 / INTEGRATION TRAPS
Memorize the seven constraints that shape the app.

        

          
VACP-001
Process-global cwd
Do not multiplex active repositories through one Vibe process. Use one session process per active Thread.

          
VACP-002
Shared configuration
Model and thinking are Vibe-home-wide in the pinned release, not honestly thread-local.

          
VACP-003
Process-bound auth
Delegated browser auth must start and complete on the same live ACP process.

          
VACP-004
Vendor auth methods
Authentication and repository trust use Vibe extensions. Keep them behind the adapter.

          
VACP-005
Replay before response
session/update history can arrive before session/load returns.

          
VACP-006
Vibe hosts tools
LeChaton observes and authorizes tools; it does not host filesystem or shell capabilities.

          
VACP-007
New is not durable
A session/new ID becomes durable only after a visible prompt and exact session/list confirmation.

Risks evolve.
